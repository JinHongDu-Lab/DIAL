# Operating Guidelines

This study measures **position effects only** — every collected condition is
anonymous (assistant labels never disclose the source model name). Unlike the
`arena_140k` study, the `anonymity` factor declares a single fixed level, so the
condition grid is 2 cells (`original_anonymous`, `swapped_anonymous`), not the
full 2×2. Identity-contrast metrics (`identity_flip_rate`,
`identity_*_probability_delta`) and the named/anonymous `position_*_named`
metrics are therefore always unavailable (`NA`) in this study's reports — that
is expected, not an error.

Use **Validate only — no API calls** to check the dataset, manifest, prompt
templates, judge configuration, and every selected condition without requiring
credentials or contacting a provider.

Use **Run experiment — uses API** only after validation. It calls each selected
judge that has at least one available configured credential. Judges whose
credentials are entirely absent are recorded and skipped; an invalid present
credential is a runtime provider error.

Run names identify audit records under `logs/runs/<run>/`. Reuse a name only
with the same dataset, prompts, judges, inference profiles, record limit, and
condition grid. Successful responses are shared and deduplicated under
`results/<judge>/`; cumulative reports are written to `reports/<judge>/`.
Run-specific errors, status, usage, effective settings, and one combined
all-judge summary remain under the run log directory.

Keep credentials in environment variables or the ignored `.env` file. Never
put keys in this manifest, prompts, output, or reports.

The manifest loads `configs/apis.json` for infrastructure and the **shared**
`../../../arena_140k/studies/position_and_anonymity/judges.json` catalog for
scientific profiles — this study does not maintain its own judge catalog.
Judge aliases name their reasoning behavior (`direct`, `low`, or `high`); do
not reuse an alias for another inference profile.

The judge panel mixes the 5 core judges shared with `arena_140k`
(GPT-4.1, Gemini 2.5 Flash, Qwen3-Next-80B, DeepSeek-V4-Flash, Claude Haiku
4.5, kept for cross-study comparability) with broader low-cost OpenAI, Gemini,
and Anthropic coverage (GPT-4.1 Mini, GPT-5.1 low, Gemini 3.5 Flash low,
Claude Sonnet 5 low). Two `ollama-*` judges are included specifically because
they overlap the JA-ranking framework's own judge roster by exact model:
`ollama-gemma-3n-e4b-direct` (`google/gemma-3n-E4B-it`) and
`ollama-gpt-oss-20b-direct` (`openai/gpt-oss-20b`). Both require a running
loopback Ollama server and the model tag pulled locally (`ollama pull
gemma3n:e4b` / `ollama pull gpt-oss:20b`), but no API key. Treat the local tag,
quantization, and digest as part of the scientific judge identity; do not
combine their cached results with a cloud deployment of the same base model.

The complete factor grid (both declared conditions) supports the paired
position causal-effect estimate. A partial grid is valid and receives the same
descriptive per-condition report, but its factorial section lists the missing
cells and remains unavailable.
Within a judge, the runner schedules selected conditions for each
record/repetition as one bundle. Thus original and swapped positions are
queried consecutively for that unit, while different records may remain
concurrent.

Successful live results enter the canonical judge file and a rebuildable
lookup index, so later compatible ranges skip them without another API call.
Validation ignores and does not update shared results. The dashboard's overall
progress describes the canonical manifest workload, independent of the
selected run log.

This study's prompt offers **3** verdict options (`a`/`b`/`c` — no `d: both
bad`), unlike `arena_140k`'s 4-option prompt. A prompt edit defines a new
scientific result generation. Before such an edit, use `causal-judge-archive
--study study.toml --label <label>` to preserve cumulative results, reports,
configuration, prompts, and cache under `logs/archives/`. Archived run names
remain read-only under `logs/runs/` but are excluded from the active Web UI
through `logs/state/generation.json`.

The dataset (`../../data/arena_33k_ja_overlap.parquet`) is generated by
`../../scripts/prepare_dataset.py`, not committed by hand — see
`../../data/README.md` for provenance and regeneration.
